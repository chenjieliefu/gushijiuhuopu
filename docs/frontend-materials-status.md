## 美学参考已到什么程度

抽查原图能确认三类现成素材：暖光木质店铺、绿色围裙的看山角色、白衬衫女孩的老街照片。店铺/角色是偏 3D 插画质感，故事照片偏写实摄影；现有素材本身包含不同表现方式，前端需要通过店内与片内的场景切换、排版和过渡统一体验。

## 最新交互流程

```mermaid
flowchart LR
    A[进入旧货铺] --> B[放映前：老板与看山交流、检查物件]
    B --> C[玩家明确选择听故事]
    C --> D[连续放映：51 单元自动播放]
    D --> E[最后单元确认完成，回到柜台]
    E --> F[放映后：交流、追问、考虑寄展]
    F --> G[寄展确认卡]
    G -->|再想一想| F
    G -->|明确确认且服务端保存成功| H[入架、告别、收藏回顾]
```

按 v4 脚本，连续放映期间隐藏聊天、检查、点击翻页、暂停、跳过和拖动进度等交互；播放前后才恢复老板与看山交流。每段展示完后通过后端 progress 确认，失败不能提前推进；中断恢复从未确认完成单元重新播放。正文与人物对白是固定内容，放映期间不调用 AI。

人物关系也已明确：**玩家是老板；看山受苏晚委托办理寄展；相机所有人是苏晚；看山不是故事中的书店男生。** 寄展需独立确认，取消不重置故事进度。

## 我们前端下一步接什么

1. 把状态与适配器扩展到新版 `phase`、`playback` 和 `/api/screening/*`；保留旧 demo 作为独立测试入口。当前 `contract.ts` / `http.ts` 未实现放映接口。
2. 整理现有 PNG 与镜头/角色/表情的映射，保留原图，生成适合网页加载的素材；新版后端配置的素材引用由团队共同对齐。25 张图不等于覆盖全部 51 个镜头，也不要求一段必须对应一张新图。
3. 实现预加载、固定字幕自动切换、当前段完成确认、失败重试和刷新恢复；保持看山与书店男生的视觉身份区分。
4. 对齐开场分支、放映后追问、寄展确认卡、入架告别和收藏。最终素材在桌面和手机中核对遮挡、裁切、文字及表情锚点。
5. 与后端跑新版完整 HTTP 流程，再验共享子域名与 HTTPS。旧版 [本地联调记录](local-integration.md) 只能证明当时探索 demo 的行为，不能证明新版播放器已通过。
