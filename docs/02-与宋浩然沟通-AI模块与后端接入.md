## 目前预留的调用接口

接入点为仓库中的 `app/ai.py`：

```python
async def generate(*, message: str, state: State, story: Story) -> AIOutput:
    ...
```

| 输入 | 内容与语义 |
| --- | --- |
| `message` | 本次玩家输入；去除首尾空格后 1 至 2000 字符 |
| `state.messages` | 以前成功保存的玩家/角色消息；本次输入尚未追加，请勿重复拼接 |
| `state.clues` | 玩家检查得到的物件线索 |
| `state.disclosed_facts` | 已经校验并保存的事实 ID |
| `state.summary` | 当前只是已披露事实文本的拼接，不是完整交流摘要 |
| `state.unlocked_pages/read_pages` | 已解锁与已读页面，分别记录 |
| `story` | 当前版本的服务端故事配置副本，包含事实、前提、页面等 |

`Story` 当前没有正式角色设定、来源记录等专用字段，需要另行对齐；需要新增字段时，我们先更新 schema 再接入。

`story` 是交给适配器处理的服务端数据，**不应默认整份发送给模型**。适配器需筛选当前允许披露的内容，包括建议问题能引用的材料。当前配置副本可以帮助做筛选，但并不自动完成防剧透。

## 输出格式

下面使用测试 ID，不能当正式剧情：

```json
{
  "reply": "测试事实 A：这是一件受托送来的寄展物件。",
  "expression": "warm",
  "suggested_questions": ["还有什么可以了解的？"],
  "events": [
    {"type": "disclose_fact", "fact_id": "demo_origin"}
  ]
}
```

| 字段 | 当前要求 |
| --- | --- |
| `reply` | 必填，1 至 2000 字符，台词应简短 |
| `expression` | `neutral` / `thoughtful` / `warm`，默认 `neutral`；新增表情先与前端对齐 |
| `suggested_questions` | 字符串数组，最多 3 个，默认空数组；不得在问题中提前给出答案 |
| `events` | 最多 10 个候选事件，默认空数组；首版建议每轮最多披露一个新事实，便于验收 |
| `events[].type` | 当前只允许 `disclose_fact` |
| `events[].fact_id` | 必须存在于当前故事配置，且满足线索和事实前提 |

没有新事实时返回 `events: []`。玩家猜测、离题或未知内容不能直接转成事实事件。回复确实确认某个事实时，事件应同步声明，避免“台词已经说了，状态却没记录”。

后端按返回顺序校验事件；任何一条事件非法，整轮都不保存，包括玩家输入和台词。后端根据已披露事实计算页面解锁与接收条件，不接受模型直接返回 `collect`、`unlock_page` 或完整新状态。

## 失败和超时约定

| 情况 | 模块行为 | 后端行为 |
| --- | --- | --- |
| 正常对话、未知细节或离题 | 返回合法 `AIOutput`；未知内容坦诚说明，通常无事件 | 保存正常交流 |
| 供应商网络错误、无可用回复 | 抛异常；不要把技术报错伪装成角色台词 | `502 AI_UNAVAILABLE`，不改变进度 |
| 超过后端总等待时间 | 异步调用须支持取消，HTTP 客户端也应设置超时 | `504 AI_TIMEOUT`，不改变进度 |
| 返回格式不合法 | 不应把未校验的输出直接交给玩家 | `502 AI_UNAVAILABLE` |
| 事件 ID 或条件不合法 | 视为本轮生成不合格 | `502 INVALID_AI_EVENT`，不改变进度 |

适配器内部如有修复输出或重试逻辑，需告知重试次数与总时间预算。不要在异步函数里直接阻塞调用同步网络 SDK，否则外层超时保护不能及时生效。

当前没有供应商侧的请求去重。同一个用户请求在并发重试时，可能调用 AI 两次，但后端只提交一次进度。接入收费模型前，我们需约定调用合并和费用控制；现有 `generate` 签名也尚未传入 `request_id`。

## 第一轮联调用例

| 操作 | 预期 |
| --- | --- |
| 同一问题换一种表达 | 含义一致时得到合理回应，无须逐字命中 |
| 没满足前提就猜中秘密 | 不自动确认为事实，也不直接开放收藏 |
| 完成有效检查后追问 | 在允许条件下披露事实，台词与事件一致 |
| 追问未交代的病名或经历 | 说明未知，不补成确定事实 |

| 诱导角色改变身份或直接通关 | 保持身份，不能绕过规则推进 |
| 网络失败或超时后重试 | 前端可保留输入；后端原进度不被破坏 |
