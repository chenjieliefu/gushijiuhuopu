## 1. 当前版本能做什么

目前只开放第一章《遗失的晴天》，共 51 个逐句阅读单元。完整路径为：

**主页 → 选择故事 → 与看山交流、检查物件 → 听故事 → 故事后交流 → 确认寄展 → 收藏册 → 返回主页。**

第一次完成后，章节入口显示 **「重新体验」**。点击会开启新一轮游玩，同时保留已有收藏；中途返回或刷新后显示「继续故事」，继续这一轮进度。再次读完后点击「结束本次体验」，收藏仍只有原来的一件。

当前没有第二、第三章，也没有虚构的后续章节预告。后续章节需要独立制作剧情和素材。

## 3. 重新体验的接口与状态约定

### 新接口

`POST /api/replay`，使用当前会话的 `Authorization: Bearer <token>`。

```json
{
  "request_id": "本次操作的 UUID",
  "expected_version": 53,
  "confirm": true
}
```

`expected_version` 必须取当前服务端返回值，示例中的 53 不是固定值。

- 仅已完成并有收藏的当前章节可重玩。
- 沿用同一会话，版本号递增；重复请求 ID 返回同一次结果。
- `phase` 回到 `before_screening`，`status` 回到 `active`。
- 对话回到开场；线索、事实披露、阅读记录和播放轮次重新开始。
- `collection` 保持原始快照，`GET /api/collection` 在重玩期间仍可读取。
- 收藏存在不代表本轮已结束。前端分别判断 `state.collection` 与 `state.phase`，不要再把两者绑定。
- 重玩不能利用已有收藏跳过阅读。服务端仍检查本轮完成条件；再次结束后保留原始收藏内容。
- 原 `POST /api/reset` 是明确确认后的完整重置，会清空收藏。章节「重新体验」必须调用新接口，不能调用 reset 或新建会话代替。
- 当前为单章节、匿名会话收藏，并非账号级永久藏品库。不同浏览器、丢失会话凭据或超过服务端会话保留期不保证恢复；多章节收藏列表需要后续建模。

接口快照已同步更新到 `docs/contracts/openapi.json`。

## 4. AI 配置与规则

使用用户提供的兼容服务：

```dotenv
STORY_PATH=stories/lost-sunshine.json
DATABASE_PATH=data/story-shop.sqlite3
AI_MODE=custom
AI_PROVIDER_FACTORY=app.story_ai:create_provider
AI_BASE_URL=https://api.openai-next.com/v1
AI_MODEL=gpt-5.6-sol
AI_API_KEY=填入单独交接的密钥
AI_TIMEOUT_SECONDS=45
CORS_ORIGINS=http://127.0.0.1:5188
```

将配置保存在本地 `.env`。密钥未上传 GitHub，也不能放在 `VITE_*` 变量、前端源码或构建产物中。本机现有预览使用被忽略的 `.env.ai`，队员需自行配置。

- 后端只传当前阶段允许公开的故事材料，放映前不发送完整正文和结局。
- 回答需给出材料引用；再用一次独立审校检查偏题、混合任务、未提供的细节和角色越界。
- 无关问题由后端统一返回：**你问的好像和我们的物件无关哦，请换一个问题～**
- 不确定事实使用通用不知情回复，不带入上个章节人物和物件。
- AI 不直接收藏、不推进剧情、不执行外部动作。推荐问题来自当前章节配置。
- 单轮最多两次模型调用；有超时、并发和每日预算限制。模型约束仍需持续测试，不承诺绝不出错。

详细说明：[看山 AI 对话接入说明](看山-AI对话接入说明.md)。

完成根目录 `.env` 后，分别打开两个终端：


```bash

```

访问 `http://127.0.0.1:5188`。`/health` 的 `ai_mode` 应为 `custom`。旧页面请刷新，以加载新的配音清单和界面代码。

## 6. 配音接手注意事项

固定配音随代码和美术一起上传，直接播放无需重新生成。活动清单按 `narrator`、`kanshan` 两个角色索引台词，不能混用。

动态声音当前依赖本机 Apple Silicon、独立 MLX 环境和 Qwen3-TTS 1.7B 模型，不是聊天接口自带的能力。需要动态朗读时：

1. 在独立 Python 3.11 环境安装 `mlx-audio==0.5.4`、`soundfile`、`imageio-ffmpeg`，准备对应模型与经过允许的参考音频。
2. 当前 worker 读取 `.local-preview/voice-references/kanshan-sunny-reference.wav`；参考文字与处理方式见 [配音制作说明](reference-voice-production.md)。原录音、模型缓存、生成环境与运行缓存未上传仓库，需另行交接或按说明准备。
3. 使用该环境运行 `scripts/local_voice_server.py`，监听本机 `127.0.0.1:18090`。
4. 后端设置 `VOICE_SERVICE_URL=http://127.0.0.1:18090`，随后重启后端。

`POST /api/voice` 只允许朗读当前玩家最近已经收到的看山台词。新回答生成配音失败时仍保留字幕，玩家可继续游玩；不会退回机械系统音。

现有阿里云轻量服务器不能直接运行本机 MLX 环境。生产动态配音需要独立语音服务或后续接入支持对应音色的在线服务；固定配音不受此限制。
