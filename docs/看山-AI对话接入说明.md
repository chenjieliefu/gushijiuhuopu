# 看山 AI 对话接入说明

## 当前接入

通过 `https://api.openai-next.com/v1/chat/completions` 使用 `gpt-5.6-sol`。该地址是用户提供的 OpenAI 兼容服务。密钥只从后端环境变量读取，本机保存在被 Git 忽略的 `.env.ai`，权限 600。

## 提示词

正式生效的提示词见 [看山角色提示词](../app/kanshan_prompt.md)。它随后端加载，不由前端或玩家覆盖。

提示词为跨章节通用规则，不固定人物、物件或交易方式。章节配置负责提供物件、人物关系、来访目的、归属与可公开事实；切换章节时使用对应材料，不把上一章节设定带入新故事。没有依据时的保底回复及二次审校规则也采用通用表述。此调整不新增章节内容。

玩家可以询问物件来历、剧情人物、动机、线索和当前章节允许的物件处理方式。无关问题统一回复：

> 你问的好像和我们的物件无关哦，请换一个问题～

## 约束方式

1. 后端按进度裁剪材料：放映前不向模型提供完整故事、结局与放映后答案。
2. 模型根据材料回答并返回对应的材料编号；编号无效时不采用回答。
3. 独立的第二次审校检查偏题、混合任务与无依据细节。生成式约束无法承诺永不出错，保留持续测试入口。
4. 收藏、进度和剧情解锁由后端规则处理，AI 不产生可执行动作。
5. 超时或格式错误不写入进度；玩家可以重试。每轮最多两次模型请求，共用后端超时和已有并发、用量限制。

## 配音

固定看山台词使用新版 20 条明亮降噪音频。新 AI 回答在本机通过相同参考音色异步生成，可以重听；不影响玩家继续阅读。动态语音依赖本机独立服务，服务器上线时须单独配置语音服务，详细见部署说明。

## 验收

已验证：物件相关自由提问、放映前防剧透、放映后身份与主题解释、缺失病名和人名不编造、无关写代码请求、混合请求及提示词覆盖要求。自动测试覆盖材料范围、固定拒绝语、无效事实引用、独立审校、语音会话范围和前端语音取消。
